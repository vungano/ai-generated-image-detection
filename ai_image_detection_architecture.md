## 1. Project Overview

**Title:** Detecting AI-Generated Images Using Dual-Branch Frequency-Spatial Fusion with Noise Residual Analysis

**Problem Statement:**
The proliferation of AI image generators (Stable Diffusion, Midjourney, DALL-E) has created a misinformation crisis — synthetic images are used to fabricate news events, manipulate elections, and undermine public trust. This system addresses that problem by building a technically robust, explainable detector capable of distinguishing real photographs from AI-generated ones without relying on watermarks or metadata.

**SDG Alignment:**
- SDG 16: Peace, Justice and Strong Institutions (combating misinformation)
- SDG 10: Reduced Inequalities (protecting vulnerable communities from synthetic media manipulation)

## 3. Dataset Strategy

### Primary Dataset: CIFAKE
- **Source:** Kaggle (CIFAKE: Real and AI-Generated Synthetic Images)
- **Size:** 60,000 training images / 20,000 test images
- **Classes:** Binary — REAL (sourced from CIFAR-10) vs FAKE (generated by Stable Diffusion)
- **Resolution:** 32×32 (upscaled to 224×224 for model input via bicubic interpolation)

### Supplementary Dataset: GenImage (for cross-generator testing)
- **Source:** HuggingFace — GenImage benchmark
- **Purpose:** Cross-generator generalisation experiment
- **Generators covered:** Midjourney, DALL-E 2, Stable Diffusion v1.4, v1.5, ADM, Wukong, VQDM, BigGAN
- **Usage:** Test set only — model never trained on this data

### Why Two Datasets?
Training on CIFAKE and testing on GenImage deliberately creates a distribution shift. This stress-tests real-world generalisation and provides the critical analysis that separates a distinction from a merit.

### Preprocessing Pipeline

```
Raw Image
    │
    ├─► Resize to 224×224 (bicubic)
    ├─► Normalise pixel values to [0, 1]
    ├─► ImageNet mean/std normalisation ([0.485, 0.456, 0.406] / [0.229, 0.224, 0.225])
    ├─► Data Augmentation (training only):
    │       - Random horizontal flip
    │       - Random rotation (±10°)
    │       - Colour jitter (brightness, contrast, saturation ±0.2)
    │       - Random crop with padding
    └─► Output: Normalised tensor (3 × 224 × 224)
```

### Fairness and Bias Considerations
- CIFAKE's real images come from CIFAR-10 which has known class imbalances across object categories
- No demographic data present — reduces identity-based bias risk
- Cross-generator test set ensures the system is not evaluated only on the generator it was trained against
- Acknowledge that detectors trained on one generator family may systematically fail on newer ones — an honest limitation

## 4. Core Technical Components

### 4.1 Branch A — Spatial CNN (RGB Features)

**Purpose:** Learn texture, edge, and structural artifacts that AI generators introduce in pixel space — unnatural smoothness, repetitive textures, distorted fine details.

**Architecture:** EfficientNet-B3 (pretrained on ImageNet)

**Why EfficientNet-B3 over ResNet?**
- Compound scaling (depth + width + resolution simultaneously) outperforms ResNet at similar parameter counts
- Better suited for subtle artifact detection vs coarse object recognition
- B3 variant balances accuracy and computational cost for 224×224 input

**Transfer Learning Strategy:**
- Phase 1: Freeze all convolutional layers, train only the classifier head (5 epochs) — establishes stable feature representations
- Phase 2: Unfreeze last 2 blocks, fine-tune with reduced learning rate (1e-4) — adapts higher-level features to artifact detection
- Phase 3: Full fine-tuning with cosine annealing scheduler — refines entire network

**Output:** 1536-dimensional feature vector (before final classification head)

---

### 4.2 Branch B — Frequency Domain Analysis (FFT Features)

**Purpose:** AI image generators operate in latent space and their outputs carry characteristic frequency signatures invisible to human eyes but mathematically detectable. Real photographs have natural 1/f frequency distributions; AI-generated images deviate from this.

**Theoretical Basis:**
The power spectral density (PSD) of natural images follows a statistical law:

```
P(f) ∝ 1 / f^α   where α ≈ 2 for natural images
```

AI-generated images deviate from this distribution, particularly at high frequencies, due to the upsampling operations in diffusion model decoders.

**Processing Pipeline:**

```
RGB Image (224×224×3)
    │
    ├─► Convert to grayscale (luminance channel)
    │
    ├─► Apply 2D Fast Fourier Transform (FFT2D)
    │       - Output: complex frequency matrix (224×224)
    │
    ├─► Compute magnitude spectrum: |FFT(x)|
    │
    ├─► Apply log transformation: log(1 + |FFT(x)|)
    │       - Compresses dynamic range for neural network input
    │
    ├─► Shift zero-frequency component to centre (fftshift)
    │
    ├─► Normalise to [0, 1]
    │
    └─► Output: 2D frequency map (224×224×1)
```

**DCT Augmentation (Discrete Cosine Transform):**
- Additionally compute DCT coefficients on 8×8 patches (mirroring JPEG block structure)
- AI generators often produce characteristic DCT coefficient distributions
- Concatenate DCT features with FFT features for richer spectral representation

**Feature Extraction:** Custom lightweight CNN (3 convolutional layers + global average pooling)
- Input: Stacked FFT + DCT maps (224×224×2)
- Output: 256-dimensional frequency feature vector

---

### 4.3 Branch C — Noise Residual Analysis

**Purpose:** Digital cameras introduce consistent sensor noise patterns (Photo Response Non-Uniformity — PRNU). AI generators cannot replicate these physical noise signatures, making noise residuals a strong discriminating feature.

**Theoretical Basis:**
Every camera sensor has a unique fingerprint embedded in its noise pattern. AI-generated images either have no noise (when generated at high quality) or synthetic noise that lacks the spatial correlation structure of real camera noise.

**Noise Extraction Pipeline:**

```
RGB Image (224×224×3)
    │
    ├─► Apply denoising filter (Gaussian blur, σ=1.5 OR
    │   Wavelet denoising using BM3D-lite approximation)
    │
    ├─► Compute noise residual:
    │       N(x) = I(x) − Denoise(I(x))
    │
    ├─► Analyse residual statistics:
    │       - Spatial autocorrelation (detects structured vs random noise)
    │       - Kurtosis of residual distribution
    │       - High-frequency energy ratio
    │
    ├─► Normalise residual map to [-1, 1]
    │
    └─► Output: Noise residual map (224×224×3)
```

**Feature Extraction:** Shallow CNN (2 convolutional layers + global average pooling)
- Input: Noise residual map (224×224×3)
- Output: 128-dimensional noise feature vector

**Why this is innovative:**
Noise residual analysis comes from digital forensics (camera identification research). Applying it to AI detection is a cross-domain contribution — few student projects, and relatively few published papers, combine PRNU-inspired analysis with deep learning for this specific task.

### 4.4 Feature Fusion Architecture

**Purpose:** Combine the three heterogeneous feature vectors into a unified representation that captures spatial, spectral, and noise-based evidence simultaneously.

**Fusion Strategy:**

```
Branch A output:  [1536-dim spatial vector]
Branch B output:  [ 256-dim frequency vector]
Branch C output:  [ 128-dim noise vector]
                        │
                        ▼
              Concatenation Layer
              [1920-dim combined vector]
                        │
                        ▼
              Fully Connected Layer (FC1)
              1920 → 512, BatchNorm, ReLU, Dropout(0.4)
                        │
                        ▼
              Fully Connected Layer (FC2)
              512 → 128, BatchNorm, ReLU, Dropout(0.3)
                        │
                        ▼
              Output Layer
              128 → 2 (Real / Fake logits)
```

**Why concatenation over attention-based fusion?**
Concatenation is simpler, interpretable, and appropriate at this scale. Attention-based fusion would be justified for much larger multi-modal architectures. The simplicity of concatenation here is a deliberate, justified choice — document this reasoning in the report.

**Ablation Study Design:**
To justify the fusion approach, train and evaluate each combination:

| Configuration | Expected Accuracy |
|---|---|
| Branch A only (baseline) | ~88–91% |
| Branch B only | ~75–82% |
| Branch C only | ~70–78% |
| A + B fusion | ~91–93% |
| A + C fusion | ~90–92% |
| B + C fusion | ~80–85% |
| A + B + C fusion (full model) | ~93–95% |

This ablation study **proves** each component contributes meaningfully — critical evidence for your evaluation chapter.

### 4.5 Custom Weighted Loss Function

**Motivation:**
Standard binary cross-entropy treats false positives (real image classified as fake) and false negatives (fake image classified as real) equally. In the real-world context of misinformation detection, a false negative is far more socially damaging — a synthetic image slips through undetected and can cause real harm.

**Proposed Loss: Asymmetric Focal Loss**

```
Standard Cross-Entropy:
    L = -[y·log(p) + (1-y)·log(1-p)]

Focal Loss (handles class imbalance):
    L_focal = -[y·(1-p)^γ·log(p) + (1-y)·p^γ·log(1-p)]
    where γ = 2 (focusing parameter)

Asymmetric Weighted Focal Loss (proposed):
    L_asym = -[α·y·(1-p)^γ·log(p) + (1-α)·(1-y)·p^γ·log(1-p)]
    where α = 0.75 (penalises false negatives more heavily)
```

**Experimental Design:**
Train the same architecture with three loss functions and compare:
1. Standard Binary Cross-Entropy (baseline)
2. Standard Focal Loss
3. Asymmetric Weighted Focal Loss (proposed)

**Metrics to compare:** Not just accuracy — compare Recall specifically (recall = how many fakes are caught), since the loss function was designed to maximise this. This demonstrates you understand the *societal purpose* of the metric, not just the mathematics.

### 4.6 Grad-CAM Explainability

**Purpose:** Produce visual explanations of model decisions — which regions of an image triggered the "fake" classification.

**How Grad-CAM Works:**
```
Forward pass → get predicted class score
Backpropagate gradients to final convolutional layer
Compute gradient-weighted average of feature maps
Apply ReLU to produce localisation heatmap
Resize heatmap to input image dimensions
Overlay heatmap on original image
```

**Application in this project:**
- Apply Grad-CAM to Branch A (spatial CNN) — shows which image regions are suspicious
- Apply separately to Branch B frequency features — shows which frequency bands are anomalous
- Compare heatmaps between correctly classified and misclassified images
- Use findings to critically discuss: *does the model focus on semantically meaningful artifacts, or spurious correlations?*

## 5. Training Configuration

| Hyperparameter | Value | Justification |
|---|---|---|
| Optimiser | AdamW | Better weight decay handling than Adam for fine-tuning |
| Learning Rate | 1e-4 (backbone), 1e-3 (fusion head) | Differential LR prevents destroying pretrained features |
| LR Scheduler | Cosine Annealing with Warm Restarts | Avoids local minima, improves generalisation |
| Batch Size | 32 | Balance between gradient stability and memory |
| Epochs | 30 (with early stopping, patience=5) | Prevents overfitting |
| Weight Decay | 1e-4 | L2 regularisation |
| Loss Function | Asymmetric Focal Loss (α=0.75, γ=2) | Penalises false negatives |
| Train/Val Split | 80/20 stratified | Maintains class balance in both splits |

## 6. Evaluation Framework

### Primary Metrics (In-Distribution: CIFAKE test set)
- **Accuracy** — overall correctness
- **Precision** — of images flagged as fake, how many are actually fake
- **Recall** — of all fake images, how many are caught (most important metric)
- **F1-Score** — harmonic mean of precision and recall
- **AUC-ROC** — model's discriminative ability across all thresholds
- **Confusion Matrix** — visualises false positive / false negative breakdown

### Generalisation Metrics (Out-of-Distribution: GenImage test set)
- Same metrics applied to unseen generator types
- Per-generator breakdown: which generators fool the model most?
- Accuracy drop analysis: quantify generalisation gap

### Robustness Testing (Adversarial Stress Tests)

| Perturbation | Purpose |
|---|---|
| JPEG compression (quality 30–90) | Simulates image sharing/re-uploading |
| Gaussian noise addition (σ=0.05, 0.1) | Simulates image degradation |
| Bicubic resizing (50% then back to 100%) | Simulates thumbnail creation |
| Brightness/contrast adjustment (±30%) | Simulates image editing |
| Social media simulation (JPEG + resize) | Real-world deployment simulation |

For each perturbation, measure accuracy degradation and identify the model's breaking point — this is genuine critical analysis.

1. Pretrained EfficientNet-B3 alone (standard approach)
2. Frequency analysis alone (Branch B)
3. Prior published approaches (cite 2–3 papers from literature review with their reported accuracies)

## 11. Ethical Considerations (Report Section Outline)

- **False Negative Risk:** Undetected synthetic images in news contexts — weighted loss function directly addresses this
- **False Positive Risk:** Real images incorrectly flagged — potential censorship and reputational damage
- **Adversarial Arms Race:** Detection systems incentivise generator improvement; acknowledge the fundamental cat-and-mouse dynamic
- **Surveillance Misuse:** A working detector could be repurposed for mass content surveillance — discuss responsible deployment
- **Training Data Provenance:** CIFAKE uses CIFAR-10 images; discuss licensing and consent
- **Generalisation Failure:** System may fail on underrepresented demographics if real image dataset lacks diversity
- **Transparency:** Grad-CAM partially addresses black-box concerns but does not fully resolve them

## 12. Future Work

1. **Transformer-based architecture:** Vision Transformer (ViT) for Branch A instead of CNN — likely better at capturing global image coherence
2. **Video detection extension:** Apply frame-by-frame analysis to detect AI-generated video (deepfakes)
3. **Continual learning:** System that updates when new generator architectures emerge without full retraining
4. **Browser-based deployment:** Export model to ONNX + run in-browser via ONNX Runtime Web — eliminates server dependency
5. **Multi-class classification:** Instead of binary Real/Fake, classify *which generator* produced the image
6. **Federated learning:** Train on distributed datasets without centralising sensitive images — privacy-preserving deployment
